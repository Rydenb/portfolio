## Popcorn

**Prediction (checkpoint B, n = 8):** linear worst case 8 checks; binary worst case floor(log2(8)) + 1 = 4 checks.

```python
import math

n = 16
linear_checks = n
binary_checks = 0 if n == 0 else math.floor(math.log2(n)) + 1
print(n)
print(linear_checks)
print(binary_checks)
```

**Actual output (n = 8):** `8`, `8`, `4`

**Actual output (n = 16, edited):** `16`, `16`, `5`

**Explanation:** Doubling n from 8 to 16 doubles the linear count (8 to 16) but binary search only goes up by one check (4 to 5), because each check halves the remaining catalog.

**Recommendation:** For a large, already sorted catalog, use binary search. If the catalog is unsorted, linear search is the safe choice unless sorting first pays off.

## MCQ

1. Binary search requires a sorted catalog with direct access to entries: **A**. Binary search halves the catalog each step, which only works if entries are in order and the middle can be reached directly.

## Homework

```python
n = 12
visits = n
pairs = n * n
print("Books:", n)
print("Visits (scan every book):", visits)
print("Ordered pairs (compare every book with every book):", pairs)
```

**Prediction:** `12`, `12`, `144`

**Actual output:**

```
Books: 12
Visits (scan every book): 12
Ordered pairs (compare every book with every book): 144
```

**Doubled catalog (n = 24):** Books 24, visits 24, pairs 576.

**Growth explanation:** Visits grow linearly, so doubling the books doubles the visits (12 to 24). Pairs grow quadratically, so doubling the books makes it four times as many pairs (144 to 576).

**Library recommendation (1,000 books):** Checkpoint B gives 1,000 worst-case checks for linear search versus 10 for binary search, so for repeated searches of an already sorted catalog, use binary search. If the catalog is unsorted, binary search cannot be used until it is sorted, and sorting costs extra work. If you keep an extra sorted copy, that costs extra memory, which is a time/memory tradeoff. It is worth it when there are many searches.

## Tests

**Main test (n = 12):** `12`, `12`, `144`

**Doubled test (n = 24):** `24`, `24`, `576`

**Empty catalog (n = 0):** Books 0, visits 0, pairs 0. There is nothing to scan and nothing to pair, so every count is zero.

**Growth explanation:** Between n = 12 and n = 24, visits doubled while pairs quadrupled, which shows that quadratic work grows much faster than linear work as the catalog grows.

## Design Thinking

- **Librarian need:** Find a book quickly in a catalog with thousands of entries.
- **Goal:** Inspect as few entries as possible while still finding the right book, or correctly reporting it missing.
- **Methods considered:** Linear search (check one at a time) and binary search (halve a sorted catalog).
- **Prototype:** A small calculator that prints the book count and the worst-case checks for each method.
- **Actual test and revision:** I ran it with n = 8 and n = 16 and saw linear go from 8 to 16 while binary went from 4 to 5. I then added labels to the homework output ("Visits", "Ordered pairs") so a librarian does not need to understand the formulas.
